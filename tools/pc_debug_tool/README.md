# 整车调试工具

整车调试工具的程序、依赖、启动脚本和说明文件统一放在 `tools/pc_debug_tool/` 下。

在项目根目录中，可以直接双击：

```text
tools\pc_debug_tool\启动整车调试工具.bat
```

也可以从命令行启动：

```bat
tools\pc_debug_tool\start_pc_debug_tool.cmd
```

如果需要手动安装依赖或直接运行 Python 程序：

```bat
python -m pip install -r tools\pc_debug_tool\requirements.txt
python tools\pc_debug_tool\pc_debug_tool.py
```

启动脚本会切换到自身所在目录，因此从任意工作目录调用都可以正确找到 `requirements.txt` 和 `pc_debug_tool.py`。工具启动后会自动搜索已配对的 `ChieftainMK10-Debug` 蓝牙串口。连接后默认保持急停，必须手动点击“解除急停”。

## 固定 PWM 标定与硬件诊断

固定 PWM 模式用于把电机、TB6612、机械传动和编码器问题与速度闭环参数问题分开。该模式绕过履带速度 PID 和堵转锁存，只保留通信超时、急停、电池截止（启用时）和 `±180` PWM 固件限幅。

架空测试用于确认方向、编码器和空载异常；最小启动 PWM、最小维持 PWM 必须在整车正常重量、履带安装完成且放在目标路面时测量。履带车辆单侧输出会包含原地转向的地面刮擦阻力，因此标定直行补偿时应让两侧同时输出，再根据跑偏情况小幅修正左右差值。

1. 首次检查方向、编码器和空载状态时将左右履带完全架空；标定整车启动/维持 PWM 时将车辆放在平整地面，并清空行驶方向上的人员、线缆和杂物。
2. 连接蓝牙并点击“解除急停”。
3. 勾选“确认周围安全，启用固定 PWM 模式”，确认安全提示。
4. PWM 调节步进为 `1`；将未测试侧设为 `0`，再按测试目的逐步调整另一侧。
5. 点击“开始输出 PWM”后输出会保持，调节数值会立即生效；再次点击“停止输出 PWM”归零。
6. 正方向检查完毕后，可用负值短暂检查反方向。

速度曲线不是上位机用编码器原始值现算的。ESP32 用 PCNT 统计 AB 编码器，在 `20-100 ms` 自适应窗口内换算速度。工具中的“履带实际速度显示”可在以下两路遥测之间切换：

- `控制反馈（PID 实际使用）`：底盘 PID 和堵转保护真正读取的速度，适合诊断控制性能。
- `平滑显示`：额外经过三点中值和显示低通，适合观察趋势，不参与控制。

判读方法：

- 履带连续转动且速度连续：电机、驱动和编码器链路基本正常。
- 履带匀速转动但仍连续出现很大毛刺：优先检查编码器 A/B 波形、外部上拉、共地、接插件和电机噪声；软件只能剔除孤立异常，不能恢复持续损坏的脉冲信号。
- 履带连续转动但速度跌到零：检查编码器供电、地线、A/B 信号和接插件。
- 履带与速度同时周期性停顿：检查机械卡滞、电源压降、驱动过热或电机能力。
- 某侧固定 PWM 完全不转：优先检查该侧驱动输出、电机接线和传动阻力。

任何时候都可以按“紧急停止”或 `Esc`。窗口失去焦点、串口断开、数据超过 300 ms 未刷新，固件都会停止底盘输出；这些安全动作也会解除上位机的 PWM 输出锁定。

## PID 手动调参

“履带 PID 手动调参”面板可以在不重新烧录的情况下修改左右履带共用的 `KP/KI/KD`：

1. 连接整车后，工具会自动读取 ESP32 当前参数。
2. 修改数值并点击“应用到内存”，ESP32 回传确认后立即生效。
3. 点击“读取当前参数”可以用 ESP32 中的实际值刷新界面。
4. 点击“恢复固件默认”会恢复 `RobotConfig.h` 中的默认参数。

参数只保存在 RAM，ESP32 重启后自动恢复固件默认值，不会把一次错误调参永久写入 Flash。左右履带共用增益数值，但两侧的积分、D 项滤波、摩擦补偿、编码器反馈和输出状态仍完全独立。建议先保持 `KD=0`，依次调好摩擦补偿、`KP` 和 `KI`；只有确认仍有超调或振荡后再加入小量 `KD`。

蓝牙串口协议使用 `PID,GET`、`PID,SET,kp,ki,kd` 和 `PID,DEFAULT`，固件以 `PID,VALUE,kp,ki,kd` 回传当前值。允许范围为 `KP/KI=0-50`、`KD=0-10`。
